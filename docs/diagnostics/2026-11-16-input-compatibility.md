# 四窗口输入问题排查

日期：2026/11/16。基于 v1.3.1 排查，修订目标为 v1.3.2。用户反馈四个游戏窗口、四个坐标、3 s 间隔时随机漏点，F6 能启动但不能停止。

## 已观察的事实

- 配置确为四点顺序模式、间隔 3000 ms、启动延时 0、持续运行、F6 启停。未修改这些用户参数。
- v1.3.1 发布记录中的 50 s 是旧配置，不用于解释当前 3 s 的反馈。
- 26 次动作 / 6 轮表示六个完整四点循环加两个动作，不能单凭此计数判断漏点。
- v1.3.1 原生输出将移动、按下、抬起放在同一次 `SendInput`；计数表示输入函数返回成功，不表示目标软件完成了业务操作。
- 四个自有顶层测试窗口收到两轮、共八对按下/抬起，顺序和落点正确；所有对的消息时间差为 0 ms。要求按住至少 30 ms 的接收目标成功数为 0/8，确认了瞬时按下/抬起的兼容性缺口。
- 现场一个游戏进程为高完整性级别 RID 12288，普通连点器为 RID 8192；其余三个沙箱进程级别更低。Computer Use 对高权限窗口明确拒绝按键控制。
- 当高权限游戏仍占前台时，第一轮自有窗口测试虽然命中目标，目标仍未收到鼠标消息；因此增加了“前台也必须属于测试窗口”的守卫。此轮不能视为点击功能通过。
- 较低权限的一个沙箱游戏窗口处于前台时，诊断钩子与生产热键窗口均收到两次 F6 和一次 Ctrl+F8。输入由 Computer Use 合成，不能视为用户物理按键复现。
- 首轮两分钟物理按键观察没有收到 F6 或 Ctrl+F8，不能据此判断热键功能。后续用户要求由代理测试。

## 鼠标按住与取消

单击改为按下、保持 50 ms、抬起；双击由两次 50 ms 按住组成，中间释放 20 ms。四个自有顶层窗口按顺序完成两轮，八次输入均满足接收端至少 30 ms 的阈值，成功数由 0/8 变为 8/8。该专项采用 150 ms 动作间隔提速，不是用户四游戏 3 s 业务验收。

双击首次按下后取消的专项先暴露了旧路径继续发送第二次按下的问题：旧结果为 2 次按下和 2 次抬起。修订后只保留 1 次按下和 1 次抬起，完成动作 0、完成轮数 0；取消异常保留，不再执行剩余半次双击。

点击间隔仍是在完整动作后的等待时间。设置 3 s 时，单击的相邻起点约间隔 3.05 s，双击约 3.12 s，另有系统调度开销。停止可中断保持和等待；已发送按下后的抬起清理不受新一轮权限预检阻断，也不补发额外单击。

## 权限预检

高权限前台占用时，即使 `WindowFromPoint` 命中自有普通窗口，`SendInput` 返回成功也未必带来目标消息，现场已观察到这一情况。新预检同时读取当前进程、前台窗口进程和目标像素窗口进程的完整性级别；当前进程无 UIAccess 且任一接收方级别较高时停止输入，提示先退出连点器后手动以管理员身份运行，或将目标改为普通权限。

查询只使用进程与令牌读取权限，每次重新查询，不跨点击缓存目标 PID 权限；不会自动提权。预检识别的是已知权限边界，不能证明目标游戏一定接受输入。

## 热键独立实验

Raw Input `NOHOTKEYS` 独立测试早期曾因无法取得普通测试窗口前台而超时，未进入有效输入阶段。后续在自有窗口获得前台后观察到：

- 同批次发送按下/抬起时，收不到 `WM_HOTKEY` 和低级键盘钩子回调。
- 保持按键 100 ms 时，同样收不到上述两类回调，但 `GetAsyncKeyState` 的按下高位可见。
- 移除 `NOHOTKEYS` 标志后，热键处理恢复正常。

这是可控环境下的兼容性证据，不能据此确认用户游戏采用该标志。现为已成功注册的启停键及 Ctrl+F8 增加 10 ms 状态采样，并与原生消息去重。最终 `--nohotkey-desktop` 退出码 0：`NOHOTKEYS` 下按住 F6 或 Ctrl+F8 100 ms 时，低级钩子仍为 0/0，但高位按键状态可见，分别得到 1 次启停或停止派发；移除标志恢复原生通道后也只派发 1 次。

同批次 0 ms 按下/抬起在 `NOHOTKEYS` 下仍未被采样捕获，未将其记为已支持。F7 继续仅使用原生热键，注册失败的组合不会经采样绕过冲突，Ctrl+F8 注册失败仍禁止启动。

## 验证进度与未覆盖项

最终 `scripts/verify.ps1` 退出码 0，Release 构建 0 警告、0 错误；核心 25/25、点选 4/4、秒制输入 5/5、托盘 12/12、对话框 7/7、只读权限预检 6/6，以及热键去重 11/11 均通过。

`--tray-desktop` 退出码 0：四点 3 s 假输出流程首个动作后用 F6 在 16 ms 内停止，再启动后用 Ctrl+F8 在 15 ms 内停止，两次均观察 3300 ms 无新增假动作，原有托盘流程也通过。

`--desktop` 在自有窗口置前后的同次运行中退出码 0，没有超时。三点两轮、三键单双击、固定坐标及真实 MainForm F6 启动通过；持续点击的 Ctrl+F8 停止为 18.5 ms，随后 400 ms 无新增；5 s 启动延时取消为 15.8 ms、零点击；重启及热键冲突释放通过。这些延迟是本次观测值，不是实时性保证。

正式安装包、便携包、安装升级和 GitHub Release 的结果统一记录在 [v1.3.2 验证记录](../releases/validation-v1.3.2.md)。

用户四个游戏的实际业务接收结果尚未完整验证，F6 在原游戏环境中的具体失效机制也尚未确定。

## 参考资料

- [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)：返回插入输入流的事件数，受 UIPI 完整性权限约束。
- [Microsoft WM_MOUSEACTIVATE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate)：目标窗口可选择激活并丢弃首次鼠标消息；本轮尚未证实游戏使用此行为。
- [Microsoft RAWINPUTDEVICE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice)：`RIDEV_NOHOTKEYS` 可影响应用定义的热键处理；本轮尚未证实游戏采用此设置。

本记录区分已观察的缺口、专项修改结果和待验证的现场原因，不替代本版发行验收。
