# 四窗口输入问题排查

日期：2026/11/16。基于 v1.3.1，用户反馈四个游戏窗口、四个坐标、3 s 间隔时随机漏点，F6 能启动但不能停止。

## 已观察的事实

- 配置确为四点顺序模式、间隔 3000 ms、启动延时 0、持续运行、F6 启停。未修改这些用户参数。
- 26 次动作 / 6 轮表示六个完整四点循环加两个动作，不能单凭此计数判断漏点。
- 原生输出将移动、按下、抬起放在同一次 `SendInput`；计数表示输入函数返回成功，不表示目标软件完成了业务操作。
- 四个自有顶层测试窗口收到两轮、共八对按下/抬起，顺序和落点正确；所有对的消息时间差为 0 ms。要求按住至少 30 ms 的接收目标成功数为 0/8，确认了瞬时按下/抬起的兼容性缺口。
- 现场一个游戏进程为高完整性级别，其余三个沙箱进程级别更低；连点器的普通权限低于该高权限游戏。Computer Use 对高权限窗口明确拒绝按键控制。
- 当高权限游戏仍占前台时，第一轮自有窗口测试虽然命中目标，目标仍未收到鼠标消息；因此增加了“前台也必须属于测试窗口”的守卫。此轮不能视为点击功能通过。
- 较低权限的一个沙箱游戏窗口处于前台时，诊断钩子与生产热键窗口均收到两次 F6 和一次 Ctrl+F8。输入由 Computer Use 合成，不能视为用户物理按键复现。
- 首轮两分钟物理按键观察没有收到 F6 或 Ctrl+F8，不能据此判断热键功能。后续用户要求由代理测试。

## 修改与验证边界

当前工作包括将点击分成按下、短暂保持、抬起，以及在输入前读取前台与目标进程权限；不自动提高权限、不补发额外单击。停止期间的抬键必须保持可执行。

默认 `scripts/verify.ps1` 已通过：核心 25/25，点选 4/4，秒制输入 5/5，托盘 12/12，对话框 7/7，新增只读权限预检 6/6；Release 构建 0 警告、0 错误。

Raw Input `NOHOTKEYS` 独立测试曾多次因无法取得普通测试窗口前台而超时，尚未进入有效输入阶段，不能据此确认或排除此原因。已请求将普通窗口置前，再继续桌面验收。F6 在用户完整游戏环境中的失效原因尚未确定。

## 参考资料

- [Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)：返回插入输入流的事件数，受 UIPI 完整性权限约束。
- [Microsoft WM_MOUSEACTIVATE](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate)：目标窗口可选择激活并丢弃首次鼠标消息；本轮尚未证实游戏使用此行为。
- [Microsoft RAWINPUTDEVICE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice)：`RIDEV_NOHOTKEYS` 可影响应用定义的热键处理；本轮尚未证实游戏采用此设置。

本记录是排查证据，不表示两个现场问题都已修复，也不是新版本发行验收记录。
