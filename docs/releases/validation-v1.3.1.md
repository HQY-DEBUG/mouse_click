- 改动前分别用跟随鼠标和三点顺序模式验证先进入托盘、F6 启动、F6 停止、再次 F6 启动及 Ctrl+F8 停止，均通过。

## 托盘与首个输出边界

`dotnet run --project tests/MouseClick.WindowsTests -c Release -- --tray-desktop` 退出码 0。

- 真实 MainForm、实际点击引擎与真实键盘输入；鼠标输出为纯计数替身。
- 三点顺序模式先进入托盘，F6 启动和停止得到 4 次动作，再次 F6 启动累计至 8 次，顺序正确。
- Ctrl+F8 停止后保持托盘状态，250 ms 内无新增动作。
- 开始按钮、F6、F9、F10 各自从可见主窗口启动，首个输出时窗口已隐藏；后续三点顺序及 Ctrl+F8 停止正确。
- 托盘中空坐标序列按 F6，主窗口恢复并显示“至少需要一个坐标”，保持停止且零新增输出。
- 托盘菜单恢复、设置取消/保存及明确退出通过，窗口和热键资源释放。

新增回归先在旧实现上分别观察到“首次输出时主窗口仍可见”和“校验失败后未恢复窗口”的失败，再在对应修改后通过。可见性由 UI 事件发布原子快照，后台输出不跨线程读取控件。

托盘菜单通过真实控件事件触发，未模拟 Windows 通知区域的物理右键或双击。

## 真实鼠标与全局快捷键

`dotnet run --project tests/MouseClick.WindowsTests -c Release --no-build -- --desktop` 在专用测试窗口前置后退出码 0：

- 三目标 `1→2→3→1→2→3` 的真实鼠标按下/抬起、像素坐标与顺序正确。
- 左、右、中键的单击和双击，以及固定模式非中心指定落点通过。
- 其他窗口处于前台时，真实主窗口通过 F6 完成三点两轮，共 6 次动作、2 轮。
- 持续点击时 Ctrl+F8 停止延迟约 17.1 ms，随后 400 ms 无新增输入。
- 5 s 启动延时可由 Ctrl+F8 取消，停止延迟约 15.4 ms，零点击。
- 停止后主窗口保持托盘状态，再次 F6 完成三点一轮，共 3 次动作、1 轮。
- 两实例热键冲突可见，释放后可重新注册。结束后测试窗口关闭，光标恢复。

仅向自有测试目标发送鼠标输入；使用独立配置，不测试用户正在运行的目标程序。以上延迟是本机本次观测值，不是实时性保证。
